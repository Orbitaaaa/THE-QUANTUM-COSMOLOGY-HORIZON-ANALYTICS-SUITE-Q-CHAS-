# G11-20 — Readout and data acquisition

## Digitiser options

| Option | Key properties (verified where cited) | Used in | Status |
|---|---|---|---|
| Shared-lab oscilloscope | ≥ 4 channels, ≥ 1.5–2 GHz analogue bandwidth, ≥ 10 GS/s; segmented memory for high trigger rates | V1 (minimal) | Borrowed; no purchase |
| PSI DRS4 Evaluation Board | 4 × 50 Ω SMA inputs; 0.7–5 GS/s; 1024 samples per channel; USB; open software (drs4eb). Available through PSI technology transfer (psi.ch/drs). Cascading to 2048 samples reduces bandwidth to ~500 MHz and must be requested at order | V2 | Price UNRESOLVED (quote from PSI) |
| Multichannel DRS4-based commercial digitiser (e.g. CAEN 742 family) | Model and specifications to be verified with the vendor | V3 (more channels) | UNRESOLVED |
| TDC-based readout (e.g. CERN picoTDC with discriminators) | Scalable to many channels; needs discriminator boards | Beyond V3 | Not planned for V1–V3 |

**Sampling.** The model gives the same resolution at 5 GS/s as at 20 GS/s for a ~0.5 ns rise. Use 5 GS/s with offline interpolation
on the DRS4.

## Triggering and synchronisation

* **Bench.** Self-trigger on plane B (OR or majority), with all planes digitised by the same board, so there is one clock.
  Calibration:
  * offsets from the median pairwise differences;
  * DRS4 timing calibration with the vendor procedure;
  * channel-to-channel jitter from a split pulser (AT-6).
* **Beam test.** A scintillator coincidence trigger. Both stations go to one digitiser (cables matched; delays calibrated with a
  pulser and a reversed-station run), or two digitisers with a distributed common clock and a trigger timestamp. An optional
  MCP-PMT reference gives absolute timing.

## Event building and data format

* Every trigger stores the waveforms for all channels, the trigger timestamp, the board temperature, the bias voltages and the
  currents.
* Storage is HDF5, one file per run, with run metadata in JSON: sensor IDs, bias, temperature, CFD settings, geometry.

## Software architecture

The reference implementation is `babyuniverse/timing11.py`, tested on simulated data.

| Layer | Function | Implementation |
|---|---|---|
| Acquisition | Configure and read the digitiser; write HDF5 | Vendor library / drs4eb, plus a Python wrapper (to be written against the real board) |
| Reconstruction | Baseline subtraction, amplitude, CFD time (linear interpolation), charge integral | `cfd_time`, `waveform`-compatible arrays |
| Selection | All planes above an amplitude cut; saturation and pile-up rejection | `analyze_run` |
| Calibration | Offsets; amplitude-walk correction (fit in 1/A); temperature monitoring | `analyze_run` |
| Physics | Pairwise widths; three-sensor solution; TOF and β | `analyze_run`, `tof_beta_resolution`, `beam_tof` |
| Monitoring | Online histograms of amplitude, time difference and rate | To be written |

**Validation already done.** On a simulated 2000-event Sr-90 run the chain recovers the single-plane resolutions within ~2 ps of
the truth, with 0.8 ps statistical uncertainty (`scripts/round11_timing.py`, `DATA/round11_timing.json`).
